# 🤖 Enterprise AI Assistant — FinSolve Technologies

An internal, role-aware AI knowledge assistant for **FinSolve Technologies**. Employees can log in and query a Retrieval-Augmented Generation (RAG) pipeline that answers questions strictly from authorised, department-specific company documents — keeping sensitive data siloed by role.

## Overview

FinSolve Enterprise Assistant answers employee questions using **only** information retrieved from internal company documents relevant to that employee's department/role. It enforces role-based access control at the retrieval layer — an HR employee will only ever receive context from HR documents, an Engineer from Engineering documents, and so on.

Key characteristics:
- **Role-gated retrieval** — document access is filtered by the authenticated user's role before any context reaches the LLM.
- **Local LLM inference** — responses are generated by a locally hosted model via **LM Studio**, so no query data leaves the organisation.
- **Prompt-injection hardened** — the system prompt explicitly guards against prompt injection from retrieved documents or user queries.

## Tech Stack

| Layer | Technology |
|---|---|
| **Frontend** | React 19, React Router v7 |
| **Backend API** | FastAPI (Python) |
| **Authentication** | JWT (HS256) via `PyJWT`, password hashing via `pwdlib` |
| **Employee Database** | SQLite (`EmployeeDatabase.db`) |
| **Embeddings** | `text-embedding-nomic-embed-text-v1.5` via LM Studio OpenAI-compatible API |
| **Vector Store** | ChromaDB (persistent, local) |
| **LLM** | `google/gemma-4-e4b` via LM Studio (local inference) |
| **RAG Pipeline** | Custom Python pipeline (document loader → chunker → embedder → vector store → retriever) |

## Prerequisites

Before starting, make sure the following are installed and running:

1. **Python 3.10+**
2. **Node.js 18+** and **npm**
3. **LM Studio** — running locally with:
   - An **embedding model** loaded: `text-embedding-nomic-embed-text-v1.5`
   - A **chat model** loaded: `google/gemma-4-e4b`
   - Local server enabled at `http://localhost:1234`

## Setup & Installation

### 1. Clone the Repository

```bash
git clone <your-repo-url>
cd enterprise-ai-assistant
```

### 2. Backend Setup

```bash
cd backend

# Create and activate a virtual environment (recommended)
python -m venv venv
venv\Scripts\activate       # Windows
# source venv/bin/activate  # macOS/Linux

# Install dependencies
pip install fastapi uvicorn pwdlib pyjwt chromadb openai markdown
```

#### Set up the Employee Database

The SQLite database is not tracked in git. You need to create it manually. Using a Python shell inside the `backend/` directory:

```python
import sqlite3
from pwdlib import PasswordHash

conn = sqlite3.connect("EmployeeDatabase.db")
cursor = conn.cursor()

cursor.execute("""
CREATE TABLE Employee (
    empId int,
    name varchar(30),
    password varchar(30),
    role varchar(30)
)""")

password_hash = PasswordHash.recommended()

# Add employees — role must match a subfolder name in data/
cursor.execute("INSERT INTO Employee VALUES (?,?,?,?)",
    (1, "Alice", password_hash.hash("password123"), "hr"))
cursor.execute("INSERT INTO Employee VALUES (?,?,?,?)",
    (2, "Bob", password_hash.hash("password456"), "engineering"))

conn.commit()
conn.close()
```

> **Note:** The `role` value stored for each employee must exactly match the corresponding subfolder name inside `data/` (e.g. `hr`, `finance`, `engineering`, `marketing`).

### 3. RAG Data Ingestion

Place your department documents into the appropriate subdirectory under `data/`:

```
data/
  hr/           ← documents accessible to employees with role "hr"
  finance/      ← documents accessible to employees with role "finance"
  engineering/  ← ...
  marketing/
  general/
```

Then run the ingestion script to embed and store all documents in ChromaDB:

```bash
cd rag
python generator.py
```

This will:
1. Walk through all files in `data/`
2. Chunk each document into 500-character chunks
3. Generate embeddings via LM Studio
4. Store them in `chroma_db/` with department metadata

> ⚠️ Make sure LM Studio is running with the embedding model loaded before running this script.

### 4. Frontend Setup

```bash
cd frontend
npm install
```

## Running the Application

You need **three** things running simultaneously:

#### 1. LM Studio Local Server
Start LM Studio, load your chat and embedding models, and enable the local server on port `1234`.

#### 2. FastAPI Backend
```bash
cd backend
uvicorn main:app --reload
```
The API will be available at `http://127.0.0.1:8000`.

#### 3. React Frontend
```bash
cd frontend
npm start
```
The app will open at `http://localhost:3000`.

## API Reference

### `POST /login`
Authenticates an employee and returns a JWT bearer token.

**Request body:**
```json
{
  "emp_id": 1,
  "password": "your_password"
}
```

**Response:**
```json
{
  "access_token": "<jwt>",
  "token_type": "bearer"
}
```

---

### `POST /user/query`
Submits a natural language query. Requires a valid Bearer token.

**Headers:**
```
Authorization: Bearer <token>
```

**Request body:**
```json
{
  "user_input": "What is the leave policy?"
}
```

**Response:**
```json
{
  "message": "Processed query for employee #1",
  "input_received": "What is the leave policy?",
  "rag_response": "<p>Answer: ...</p><p>Sources: ...</p>",
  "user_role": ["hr"]
}
```

> The `rag_response` field contains HTML-rendered markdown, ready for `innerHTML` injection in the frontend.

## Security

- **JWT Authentication** — all query endpoints require a valid, unexpired (30-minute) HS256 JWT.
- **Role-based retrieval** — ChromaDB queries are filtered by the authenticated user's department role. Employees can only receive context from their own department's documents.
- **Prompt-injection defence** — the system prompt explicitly instructs the LLM to ignore any instructions embedded in retrieved documents or user queries.
- **Local inference** — all LLM inference and embedding generation happens on-device via LM Studio. No data is sent to external APIs.
- **Password hashing** — employee passwords are stored as bcrypt hashes using `pwdlib`.

## Data Organisation

Documents placed in `data/` are automatically tagged with the subdirectory name as their `department` metadata in ChromaDB. The directory name **must match** the `role` column in the Employee database.

```
data/
  hr/            → department: "hr"
  finance/       → department: "finance"
  engineering/   → department: "engineering"
  marketing/     → department: "marketing"
  general/       → department: "general"
```

Supported file types depend on what your document loader can read as UTF-8 text (`.txt`, `.csv`, `.md`, etc.).
